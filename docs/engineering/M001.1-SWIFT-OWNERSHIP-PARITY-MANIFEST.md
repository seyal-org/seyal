## Product decision

The existing Swift product implementation is **rejected as product truth**.

```text
Rust = only authoritative Seyal product implementation

Swift = new thin macOS host created later from scratch (#883)
        only AppKit / IME / accessibility / clipboard /
        Metal / CoreText / macOS-specific integration
```

Do **not**:

- treat XCTest/XCUI green as product progress;
- port `SeyalShellState` or equivalent Swift state machines into a new Swift host;
- use `PRESERVE_PARITY` as a category;
- grow features on the frozen shell;
- run two writable product models (`SeyalShellState` plus a new Rust reducer) on the same domain.

`macos/Seyal` may be inspected only to discover required capabilities, reusable macOS glue, and obsolete code/tests to delete.


#890 is the independent removal task. It is **not** #884 (fixtures after Rust contracts) and **not** #883 (new host). It may land when docs/CI can tell the truth, even if no headed production `Seyal.app` remains.

PR #903 / `remove-all-swift` is the **umbrella recovery branch** for that removal. Its current head deleted the rejected Swift product shell **and** the then-current native host sources. That deletion of deprecated product authorities is preserved. It is **not** accepted architecture to leave the repository without a replacement native adapter.

`KEEP_NATIVE_GLUE` now means **recreate this concern** in #883, not “the deleted file is still present.” Required native concerns:

- `NSApplication` / `NSWindow`
- `NSEvent` capture / primitive normalization
- `NSTextInputClient` / IME preedit
- NSAccessibility realization of the Rust semantic snapshot
- `NSPasteboard`
- `CAMetalLayer` / Metal / CoreText
- trusted helper spawn

Do **not** restore `SeyalShellState`, preview models, `PanePresentationSession`, Swift composer/Block/recovery policy, or old product-authority tests.

#903 remains **unmergeable to `master`** until a real application passes headed acceptance. #904 freezes the Rust/native contract only. This documentation task does **not** restore `Seyal.app` and does **not** satisfy the Usable Terminal Gate.

## Remaining implementation gaps

These remain open after #904. Closing them is out of scope for this documentation task:

- no headed `Seyal.app`
- no Usable Terminal Gate
- no new thin host (#883)
- no Rust application-root / Workspace/Tab/Pane product reducer (#879) consumed by a host
- PR #903 unmergeable until headed acceptance
- native adapter concerns must be recreated; they are not optional because their sources were deleted

Rust children wait until this freeze is **accepted**. Parallelize Rust work only where state ownership and files do not overlap. Every feature needs Rust tests before native integration.

## Crate homes (no new GUI framework)

Reuse existing crates. Do **not** add a cross-platform GUI toolkit crate. Do **not** add a `seyal-client → seyal-runtime` production edge.

| Concern | Rust home |
|---|---|
| `WorkspaceId` / `BlockTimeline` / execution registry | `seyal-runtime` (already canonical; do not fork) |
| Workspace/Tab/Pane/split/focus product domain + snapshots/actions | smallest justified host-facing module, expected in `seyal-client` (or `seyal-core` value types only) |
| Theme/config/semantic tokens | `seyal-client` cold config + `seyal-core` value types if shared |
| Flow/Raw/TUI presentation policy | `seyal-client` product presentation; Runtime/VT unchanged |
| Composer draft/submit fencing; Block **projection** | `seyal-client`; Runtime `BlockTimeline` stays the Block authority |
| Reconnect/retry/deadline **policy** | `seyal-client`; Runtime/PTY survival remains #719 |
| Agent/inspector/attention projection | `seyal-client` projection over Workspace + activity sources |
| Prepared frames / Metal bind | `seyal-render` + existing FFI; unchanged by this freeze |

Boundary: coarse typed actions/events in, snapshots/projections out. No JSON/chatty FFI. No per-cell/per-glyph Rust↔Swift calls.

## Dual-authority rule

Until #890/#883/#884 complete:

- no feature work on deprecated Swift product types;
- no Swift writer **and** Rust writer on the same domain;
- old XCTest green is not M001.1 progress;
- Rust tests are the product spec for step 2;
- headed proof is the **new** `Seyal.app` (#885).

#890 / PR #903 may remove the rejected shell from the supported path **before** #883 exists. That can leave the recovery branch without a headed app. Required: remaining Rust/runtime is production-grade; docs/CI describe the real surface; `KEEP_NATIVE_GLUE` concerns are recreated, not forgotten because the files were deleted. #903 must not merge to `master` by weakening native acceptance.
