# Seyal support

This repository is the public OSS foundation for Seyal.

## Use GitHub Issues for

- reproducible bugs;
- regressions;
- accepted feature/proposal work using the appropriate Issue form;
- architecture/R&D proposals that are safe to discuss publicly;
- documentation defects.

Before opening an Issue, search existing Issues and read `CONTRIBUTING.md`.

A useful bug report includes the exact Seyal revision/build, platform, reproduction steps, expected behavior, actual behavior and relevant non-sensitive logs/evidence.

## Do not use public Issues for

- exploitable vulnerability details;
- credentials, tokens or secrets;
- private infrastructure details;
- sensitive terminal contents.

Security reports follow `SECURITY.md` and the repository's private GitHub Security Advisory/private-reporting flow when enabled.

## Questions and troubleshooting

First consult:

- `README.md` for project entry points;
- `CONTRIBUTING.md` for contribution workflow;
- `docs/engineering/DEVELOPMENT.md` for build/test workflow;
- `docs/architecture/c4/README.md` for architecture orientation;
- `docs/engineering/COMPATIBILITY.md` before assuming a platform/tool is supported.

If the question exposes a reproducible product or documentation defect, open an Issue using the closest matching form.

## Support expectations

Seyal OSS is developed in public, but opening an Issue does not create an SLA. Maintainers prioritize work according to correctness, security, active milestone scope, regressions and available capacity.

Please keep one actionable problem per Issue unless several symptoms share one proven root cause.
